# Habit tracker workspace

This repository owns all documentation, agent instructions, and agent skills for the habit tracker. The implementations are separate Git repositories under `repos/`, which this outer repository ignores.

## Repositories

- `repos/web-app/`: the local-first frontend.
- `repos/backend/`: authentication and optional cross-device synchronization.
- `repos/habit-strength/`: a standalone browser playground for experimenting with habit strength algorithms and parameters.
- `repos/tinybase-app/`: a reference todo app generated by `create-tinybase`. Use it as an example of the TinyBase client-server sync setup.

## Docs

Shared product behavior in `docs/product/`:

- Product direction: `vision.md`
- Domain vocabulary: `glossary.md`
- Habit behavior: `business-rules.md`
- User needs and flows: `user-stories.md` and `user-flows.canvas`
- Account and synchronization behavior: `sync-contract.md`

Implementation docs per repository:

- Web app: `docs/web-app/architecture.md` for frontend structure, `docs/web-app/adr/` for prior implementation decisions, `docs/web-app/features.md` for delivery work.
- Backend: `docs/backend/architecture.md` for implementation boundaries and stack, `docs/backend/features.md` for delivery work.

Read the sources relevant to the task. For a change spanning both implementations, read both architecture docs and the sync contract before proposing or changing behavior.

Keep product behavior in `docs/product/`, and stack and implementation details in the matching `docs/<repo>/`. Record a decision that constrains both implementations in `docs/adr/`. Record a decision for one implementation in `docs/<repo>/adr/`.

## Verification

Use each repository's `package.json` scripts for build, formatting, checks, type-checking, and tests. Run them from that repository's directory. `package.json` is authoritative.

## Git boundaries

The outer repository owns docs, agent instructions, and skills. Each child repository owns its code and configuration. Run status, diff, commit, and `gh` issue or pull-request commands in the repository that owns the changed files.
